# 파일 위치 선정 규칙

새로운 문서를 생성하거나 기존 문서를 재배치할 때 지켜야 하는 규칙입니다.

---

## 1. 폴더 선택

### 선정 기준
- 기존 트리를 직접 훑어(`ls`·`Glob`) 같은 주제의 폴더가 이미 있는지 먼저 확인한다. 폴더 근거는 실물 트리뿐이다

### 폴더 = 같은 주제 파일 모음

한 폴더는 **같은 주제**의 파일들을 담는다. 같은 하위 주제(도구·라이브러리·세부 개념 등) 파일이 **2개 이상** 모이면 그 하위 주제로 자식 폴더를 만든다. 파일이 하나뿐이면 부모 폴더에 flat하게 둔다. 이 판단은 지금 놓는 문서의 자리에만 쓴다.

- 나중에 2번째 파일이 생기면 그때 폴더로 접는다. 미러를 함께 옮기는 법은 [원본 이동 시 미러 동반 이동](directory-roles.md#원본-이동-시-미러-동반-이동)을 따른다.

---

## 2. 파일명 작성

파일명은 **검색 용이성**과 **내용 명확성**을 고려하여 작성합니다.

### 명명 규칙
- 핵심 키워드를 파일명에 포함
- 너무 길지 않게 (2-4 단어 권장)

---

## 3. 문서 분할

### 길이 상한

**knowledge 문서는 400줄을 초과할 수 없다.**
분할, 꼬리질문 분리, 답변 축약 등 구체적 액션은 사용자가 판단한다.

### 나누는 두 방식 — 곁가지로 떼기 vs 대등하게 쪼개기

큰 문서를 나눌 때 방식이 둘이다. **주인이 있느냐**로 고른다.

| | 곁가지로 떼기 (`<name>.sub.md`) | 대등하게 쪼개기 (폴더) |
|---|---|---|
| 관계 | 본편이 주인, 곁가지가 딸림 | 주인 없음. 나뉜 파일들이 나란함 |
| 나누는 기준 | 취급 — 덜 외워도 되거나, 본편을 지정해 `/exam`·`/review`할 때 함께 나오지 않게 하고 싶은 질문을 덜어냄 | 주제 — 서로 다른 주제가 한 파일에 섞여 있음 |
| 결과 | 본편 이름·경로 그대로, 옆에 `.sub.md` 하나 추가 | 원본이 사라지고 새 이름 파일 여럿 생김 |

주제가 여럿이면서 그중 하나가 덜 중요한 경우엔 **먼저 폴더로 쪼개고**, 쪼갠 파일 각각에서 다시 곁가지를 뗀다.

### 곁가지 분리 — `<name>.sub.md`

원본 `<name>.md`에서 "덜 기억해도 되는" 질문만 떼어 같은 폴더의 `<name>.sub.md`로 옮긴다. 본편은 이름이 바뀌지 않으므로 본편을 가리키는 링크는 그대로다. 옮긴 질문의 explained 섹션은 `explained/<rel>.sub.md`로 함께 옮긴다.

- **frontmatter**: `tags`·`source`는 본편과 같게 두고, `priority`는 두지 않는다 — 덜 중요해서 덜어낸 파일이다.
- **문서 통째로 덜 중요해지면**: 파일명 대신 frontmatter `priority`를 사용자가 정한 값으로 낮춘다([priority](content-format.md#priority)). `.sub.md`는 한 문서 안에서 일부 질문을 덜어내는 도구다.
- **본편을 지우게 되면**: 곁가지를 본편 이름으로 개명한다(`<name>.sub.md` → `<name>.md`, explained 미러도 함께) — `.sub` 꼬리표는 본편이 따로 있다는 표시다.
