# Digest — ON·루프

`ON [URL]`부터 `OFF` 입력 전까지 따른다.

## ON — 모드 시작

1. **준비** — 출처 URL을 기록하고, [SKILL.md](SKILL.md) 「slug는 ON의 URL로 정해 끝까지 쓴다」대로 slug를 얻어 `npm run --silent digest -- reset <slug>`로 질문 로그를 비운다. `npm run --silent digest -- page <URL>`로 페이지 원문을 받아 둔다 — 한글 요약과 0단계 대조가 이 원문을 쓴다.
2. **한글 요약** — 받아 둔 원문을 읽고 페이지 전체의 한글 요약을 출력한다. 내용 개요에 더해 아래 축으로 나눈다.
   - **실질적 쓰임새 차이**: 이 페이지를 알면 개발자의 코드 작성 방식이 직접적으로 달라지는 내용
   - **몰라도 지장 없는 내부 원리**: 알면 유익하지만 코드 작성법 차이를 직접 유발하지 않는 내부 동작·인프라 수준의 내용
3. **겹치는 것 알리기** — 이 주제로 KA에 이미 있는 것을 요약 뒤에 목록으로 보여준다. 아래를 모두 훑는다. **URL**·**백로그**는 메인이 직접 찾고, **주제**는 Explore 서브에이전트(`model: sonnet`)에 페이지가 다루는 개념·태그를 넘겨 맡겨 겹치는 파일 경로와 질문 제목만 돌려받는다.
   - **URL**: `npm run --silent digest -- refs <URL>`이 내는, 출처 URL이 걸린 knowledge 파일
   - **주제**: 페이지가 다루는 개념·태그·폴더로 knowledge/를 grep — URL이 안 걸려도 한다.
   - **백로그**: 프롬프트마다 뜨는 백로그 목록 중 그 주제 항목

   **손댈 범위는 언제나 겹치는 것 전체다 — 묻지 않는다.** 목록은 "무엇이 갈릴 수 있는지" 알리는 통보이지 승인 요청이 아니므로 곧장 안내로 넘어간다. 사용자가 특정 파일을 빼라고 말하면 그때 그 파일만 뺀다.
   파일마다 어떻게 할지는 페이지를 다 읽은 뒤 OFF에서 질문을 확정할 때 정한다. 아직 안 읽은 뒷부분이 기존 문서 내용을 근거로 쓸 수 있기 때문이다.
4. **안내** — 담을 것: digest 모드 시작, 단락을 붙여넣으면 문장마다 해설한 화면을 브라우저로 띄운다는 것, 거기서 문장마다 저장·해설·버림을 고르고 복사된 JSON을 붙여넣으라는 것, 페이지를 끝까지 본 뒤 OFF 하면 저장으로 고른 것만 모아 질문을 뽑는다는 것.
5. 영어 단락이 URL과 함께 왔으면 그 단락을 「루프 — 페이지 순회」로 넘긴다.

## 루프 — 페이지 순회

사용자가 단락을 붙여넣을 때마다 아래를 수행한다.

### 0. 원본 페이지 검증

붙여넣은 단락이 이 페이지 원문에 글자 그대로 있는지 `npm run --silent digest -- has <URL>`(단락을 heredoc stdin으로)로 대조한다.
`<URL>`은 지금 순회 중인 페이지 URL이다(아래에서 새 URL을 받았으면 그 URL).
Official Answer는 원문 그대로여야 하므로 한 문장이라도 다르면 해설하지 않고, 다른 문장과 그 자리의 원문을 보여 주며 다른 페이지의 단락인지 묻는다.
다른 페이지라며 새 URL을 주면 `page`로 그 원문을 받아 다시 대조하고 해설로 넘어간다.

### 1. 문장마다 [인용 → 해설] — 브라우저 페이지로 낸다

붙여넣은 단락의 **모든 문장·코드블록**을 문장 하나당 카드 한 장으로 만든다. 나눠 학습하고 싶다고 하면 이번 분량을 다 담은 뒤 "다음부터 한 단락씩 붙여넣어 주세요"라고 안내한다.

1. **원문 인용** — verbatim으로 그대로 옮긴다. 이 인용이 OFF에서 Official Answer의 원본이 된다.
2. **한글 의역** — 판정과 상관없이 원문 의미를 한국어로 푼다. 의역만 봐서는 알 수 없는 근거가 있을 때만 의역 뒤 괄호에 한 문장으로 덧붙인다. 그런 근거는 아래뿐이다.
   - 기존 knowledge 파일과 겹치거나 거기에 붙일 재료 (`knowledge/<경로>.md`를 적는다)
   - 이 페이지가 아니라 다른 페이지·다음 절에서 다룰 범위
   - 앞서 저장 판정한 선행 개념에서 그대로 도출되는 내용
   - 실무에서 드물어 버림으로 둔 이유 (§2 「이론적 타당 ≠ 실무 빈도」)
3. **영단어 해설** — 그 안의 중요 영단어와 이 문장에서의 의미를 짚는다. 짚을 단어가 없으면 생략한다.
4. **라디오 3택** — 저장 / 해설 / 버림. 기본 선택은 AI 판정으로 미리 찍어둔다 (§2).

2·3은 `local/contexts/explanation-guide.md` 「포맷」의 「본문」 의역·영단어 해설 양식과 「끊는 기준」, 「금지」를 따른다 — 카드를 쓰기 전에 그 파일을 연다.
기억으로 쓰면 그 파일의 금지를 어긴다.
「본문」의 `>` 블록쿼트 인용·`- **단어**:` 표기와 「조각 순서」는 카드에 적용하지 않는다(원문은 `src`에, 단어는 `words`에, 순서는 원문 순서대로).

- 긴 문장은 「끊는 기준」대로 쪼개 `ko`에 조각마다 `<p>`로 의역을 나눠 적고, 영단어 해설은 조각 구분 없이 `words`에 원문 순서대로 모은다. 카드는 문장 하나에 하나이므로 라디오도 하나만 둔다.
- 코드블록·삽화 캡션은 영단어 해설 없이 [인용 → 한 줄 설명 + 라디오]로 처리한다.

무엇이 학습가치가 있고 없는지를 AI가 미리 정해 **해설을 건너뛰지 않는다.** 해설에는 **스킵("넘어간 것") 경로가 없다** — 거르는 일은 라디오가 하고, 해설은 전부 한다.

**깊이는 학습가치에 비례해 조절**한다:

- 개념·정의·실무 함의가 있는 문장 → 인용 + 충실한 해설 + 필요한 용어 풀이
- 수사적 도입·전환·군더더기 문장(비유, "다음 섹션 예고" 등) → **인용 + 한 줄 의역**으로 처리한다. 역할을 짚고 싶으면 의역 뒤에 한 마디 붙인다.

#### 페이지 만들기·열기

카드 내용을 스펙 JSON으로 적어 아래 명령으로 넘긴다.

**스펙 JSON은 레포 안에 만들지 않고 `os.tmpdir()` 아래에 쓴다.** 아래를 한 번에 실행한다. 중간 파일·최종 HTML 모두 임시 폴더에 떨어지므로 뒤처리하지 않는다.

```bash
SPEC="$(node -p 'require("os").tmpdir()')/ka-digest-<slug>-<회차>.json"
cat > "$SPEC" <<'SPEC_JSON'
{ ...스펙... }
SPEC_JSON
npm run --silent build-page -- digest-cards < "$SPEC" \
  | node "{{contexts}}/local-html-roundtrip.mjs" open ka-digest - --slug <slug>-<회차>
```

스펙은 `{ slug, round, summary, cards: [{ src, ko, words: [{ word, meaning }], verdict }] }`이고, 필드가 위 네 칸과 1:1이다 (`verdict`는 라디오에 미리 찍어둘 AI 판정 — `save`·`explain`·`drop`).

- `<slug>`는 ON에서 얻은 값이다. `<회차>`는 이 세션의 붙여넣기 순번(1부터).
- `ko`·`words`·`summary`는 이스케이프 없이 HTML로 들어간다. 굵게·코드 표시는 `<strong>`·`<code>`로 쓰고, 글자로 보여야 할 `<`·`>`·`&`는 `&lt;`·`&gt;`·`&amp;`로 쓴다.

#### 채팅에 쓰는 것

페이지를 열면 채팅에는 문장 수·회차, 열린 HTML의 절대경로, 문장마다 고른 뒤 제출·클립보드 복사를 누르고 복사된 JSON을 붙여넣으라는 안내만 남긴다.

**순회 중 사용자가 채팅으로 물으면 채팅에 답한다** — 위 제한은 페이지 안내에만 걸린다. 답한 뒤 [SKILL.md](SKILL.md) 「세션 중 질문은 질문 로그에 남긴다」대로 기록한다.

### 1-1. 단락 요약

카드가 끝나면 단락 전체의 핵심을 비유와 함께 3줄 이내로 정리해 스펙의 `summary`에 담는다.

### 1-2. 선택 받기

사용자가 붙여넣은 JSON이 선택 결과다. 쓰는 필드는 `items[].head`와 `items[].verdict`(`save`·`explain`·`drop`)다.

- `__skill`(`ka-digest`)·`slug`·`round` 중 하나라도 이번 페이지와 다르면 다른 페이지의 값이므로 "이 세션에서 방금 연 digest 페이지의 클립보드 복사를 다시 눌러 붙여넣어 주세요"라고 안내한다.
- 받은 선택은 **원문과 짝지어 세션 안에 쌓아둔다.** `head`로 대조해 순서가 어긋나지 않았는지 확인한다. 이 누적이 OFF에서 저장 후보를 모을 때의 입력이다.
- 받은 결과는 채팅에 한 줄로만 보고하고 다음 단락을 요청한다.

### 2. 저장 판정

판정은 카드 라디오의 기본값으로 찍는다. 아래 기준은 그 기본값에 적용하고, 최종 결정은 사용자가 화면에서 한다.

#### 세 판정의 목적지

세 판정은 강도가 아니라 **목적지**로 갈린다 — 저장은 `knowledge/`의 Q&A 재료, 해설은 `explained/`의 해설 재료, 버림은 아무 데도 안 남는다.

「해설」이 맡는 것은 **그 자체로는 외울 게 없지만 남이 읽을 때 이해를 돕는 문장**이다.

- 앞 문장의 개념을 그대로 풀어 보이는 예시·비유
- 사용자 도메인 안에서 개념의 적용 범위를 넓혀 보여주는 사례 (도메인 밖 사례는 버림 — 아래 「사용자 역할 기준 필터링」)

「버림」으로 남기는 것은 문서 유지보수 배너·목차 링크·계보 귀속처럼 해설에 실어도 독자에게 아무 도움이 안 되는 문장이다.

#### 버림·해설 판정 기준

knowledge에 안 넣는 기준은 **"알 필요가 없는가"**다. 쉽다·상식이다·나중에 더 배울 것 같다는 사유가 아니다.

**사용자 역할 기준 필터링**: 사용자의 역할·배경이 명확하면 그 역할과 무관한 전문 분야 내용은 기본값을 「버림」으로 둔다.
- 비개발 도메인 적용 사례(의료·반도체·물류 등) → 개발자 사용자에게 버림
- 구현·운영 레벨 세부사항(모델 내부 회로, 인프라 설계 등) → 일반 사용자·소비자 역할에게 버림

**상대편이 쓰는 API는 내 코드가 달라질 때만 저장한다**: 사용자의 역할이 한쪽(웹)인데 문서가 양쪽(웹·앱, 프론트·백엔드)을 함께 다루면, 상대편이 부르는 이름 자체는 저장하지 않는다.
가르는 것은 **그것 때문에 내 쪽 코드가 달라지는가**다. 달라지면 저장하되 질문은 내 쪽 결과를 묻는 각도로 세우고, 안 달라지면 해설로 내린다.
- **그 API가 왜 생겼는지의 플랫폼 사정**도 같은 축에서 버림이다. 상대편 사정이라 내 코드를 안 가른다.

**이론적 타당 ≠ 실무 빈도**: 1차 소스 근거가 있어도 사용자 역할의 하위 맥락에서 마주칠 빈도가 낮으면 기본값을 「버림」으로 두고, 의역 뒤 괄호에 왜 드문지 메커니즘을 적는다.

**기계적 후속은 「해설」로 찍는다**: 같은 페이지에서 이미 「저장」한 개념에서 기계적으로 유추되는 API 사용 세부(값을 어디서 꺼내는지, 옵션을 어느 인자에 얹는지)는 「해설」로 두어 OFF에서 선행 질문의 해설에 흡수한다. 가르는 질문은 "그 개념을 알면 외울 게 아니라 그때 찾아보면 되는가"다 — 난이도가 아니라 선행 개념에서의 도출 가능성이다.

**계보는 버리고 효용·지침은 저장한다**: 개념의 기원·귀속, 몇 가지 형태로 분류되는지, 어느 책·논문에 실렸는지는 버린다. 그것으로 무엇이 좋아지는지, 무엇을 하라는지, 대가가 무엇인지는 저장한다. 가르는 것은 형식(나열이냐 산문이냐)이 아니라 그 문장이 독자를 판단·행동하게 만드는가다.

**이미지 alt text·캡션은 버림**: 붙여넣은 텍스트에 섞여 들어온 이미지 alt text·캡션(주어-서술어 구조가 없는 나열형 문장)은 Official Answer 재료가 아니다.

#### 중복 검사

판정에 앞서 붙여넣기(단락)마다 한 번, 문장이 아니라 단락 전체를 놓고 수행한다.

- URL 출처가 무매칭이어도 개념·태그·파일명·폴더로 knowledge/를 따로 grep한다 — 같은 내용이 다른 출처 파일에 있을 수 있다.
- knowledge/ 밖 형제 레포 docs(MP `docs/patterns/`·`docs/best-practices/`)도 grep한다 — 테스트·컨벤션·원칙은 MP에 사는 일이 많다.
- 기존 Official Answer와 **완전히 동일한 문장**이면 「버림」
- **같은 개념의 다른 표현**(더 쉬운 설명, 다른 관점, 보충)이면 「저장」

단, ON 겹침 목록에 있고 이번 재료가 그 내용을 대체·개정하는 파일과 겹치면 중복이 아니라 갈아끼울 자리라 「저장」으로 찍는다.
